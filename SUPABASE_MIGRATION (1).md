# План перехода на Supabase (production)

**Статус: интеграции с Supabase в проекте НЕТ.** Сейчас сайт — статическая демо-версия: данные, сессии и «авторизация»
живут в браузере посетителя (`localStorage`/`sessionStorage`) и не являются защитой. Файл `supabase/001_schema_DRAFT.sql`
— черновик схемы и RLS-политик; он **не применялся и не проверялся на живой базе**.

## Шаги
1. Создать проект Supabase. В frontend использовать только `anon`-ключ (он публичный по замыслу). `service_role` — никогда
   не помещать в репозиторий и в браузерный код; он нужен только серверным функциям/CI.
2. Проверить и применить `supabase/001_schema_DRAFT.sql` (SQL Editor или `supabase db push`). Проверить политики RLS отдельным
   набором тестов под ролями `anon`, `authenticated`, `moderator`, `admin`.
3. Авторизация: Supabase Auth (email/magic link или логин+пароль). Роль хранится в `profiles.role` и меняется только
   администратором. Проверка «админ» — исключительно через RLS (`is_admin()`), а не через флаги в `sessionStorage`.
4. Приглашения: только через RPC `redeem_invite` (код не читается клиентом). Регистрация по приглашению — серверная функция.
5. Медиа: bucket `media` в Supabase Storage вместо base64 в `localStorage`; лимит размера и MIME-типов на стороне Storage.
6. Миграция данных: `tests`-совместимый экспорт демо-базы (админка → «Резервная копия») преобразовать скриптом в INSERT'ы:
   users→profiles (после создания auth-пользователей), categories, threads+posts, invites, site_settings (`site`, `links`,
   `homeLabels`), pages (`rules`,`help`), media/ads. Числовые «демо-счётчики» (`stats`, `categories.topics/messages`, `threads.answers`)
   в production должны **вычисляться** запросами/представлениями, а не храниться.
7. Frontend: заменить обращения к `DEMO_DB`/`saveDB()` слоем доступа к данным (`supabase-js`), сохранив рендеринг страниц.
8. Санитизация HTML страниц «Правила/Помощь» — и при записи (Edge Function), и при выводе (как сейчас `sanitizeHtml`).
9. Включить защиту от перебора (rate limits Auth), CAPTCHA на регистрации, журнал действий модераторов.

## Что остаётся только демо
Синтетические пользователи/сообщения, «депозиты», «USDT», «гарант» в профилях — демонстрационные значения без внешних сервисов.
